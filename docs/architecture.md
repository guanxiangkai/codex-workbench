# 架构与扩展指南

## 分层

| 层 | 主要位置 | 职责 |
| --- | --- | --- |
| 展示积木 | `ui/readonly-primitives.js` | 无状态搜索框、选择框、数量、空态、工具栏，注入转义与图标依赖 |
| 页面协调 | `ui/readonly.js` | 模块视图、查询状态、详情、事件与宿主桥接 |
| 样式和入口 | `ui/readonly.css`、`ui/app.html` | 共用视觉规则、嵌入入口 |
| 发布装配 | `ui_resources.py`、`ui_release.py`、`publish_ui.py` | 内联依赖、内容版本、完整发布快照 |
| 应用服务 | `service.py`、`catalog.py` | 公开工具契约、模块路由与受控业务操作 |
| 来源适配 | 各 `*_catalog.py`、账户及知识适配器 | 规范化外部数据，隔离来源差异 |
| 本机运行 | `runtime.py` 与快照存储 | 服务生命周期、后台采集、缓存与恢复 |

文件名在后端层均相对于 `src/codex_workbench/`。

## 使用的模式与选择依据

**组合与工厂。** `createWorkbenchReadonlyPrimitives` 创建一组纯渲染函数；页面组合它们，组件不读取全局页面状态，不自行请求数据。转义和图标以依赖注入提供，测试可使用合成依赖。先统一高频积木，不为一次性视图建立深继承树。

**适配器。** 账户、模型、保险库与知识来源通过明确契约投影到页面需要的数据。新增来源应扩展适配器和登记，不在视图里散布供应商网络调用。

**目录登记。** 模块及工具元数据由 catalog 集中声明。新增模块同步登记工具、UI 入口和数据契约，避免导航与实际能力不同步。

**快照读取与后台采集分离。** 页面读取已完成结果，后台采集发布新快照；失败保留旧结果。同模块去重和并发上限由运行层负责，展示组件不管理采集锁。

**内容寻址发布。** HTML 与工具声明进入同一发布快照，摘要参与资源 URI，防止宿主缓存仍指向旧界面。修改源码不等于发布，生成 release 也不等于目标实例已加载。

## 新增组件

1. 先确认至少两个调用点共享语义，或一个组件有明确扩展需要。
2. 使用参数传入展示上下文；文本统一 escape，不接受任意未经处理的来源 HTML。
3. 组件只返回标记，事件由页面协调层管理；ID、可访问名称及样式契约保持稳定。
4. 新脚本必须加入 HTML 装配和源码刷新依赖；直接执行页面脚本的测试也必须加载它。
5. 检查当前交互，不用仅复述模板的测试充数。

## 新增来源或模块

先定义非秘密元数据、稳定 ID、失败语义和权限边界，再写适配器。列表与详情必须从同一权威投影读取。来源缺失不等于空结果，未知用量不等于零。第三方接口失败不可吞成成功。秘密只传引用，不能放进 JSON 目录、页面快照或日志。

JSON 分片按记录 ID 拆分，重复 ID 应拒绝；迁移先预检和比较公开投影，再保留恢复副本。拆分不替代并发写入控制。

## 发布流程

任务分支经过 dev、test、main 的 PR 与项目规定 CI。`publish_ui.py` 校验 JavaScript、组件与页面行为及加密互操作后生成发布快照。上线前保护运行目录中其他任务的未提交改动，准备可恢复副本，再部署对应文件并启动服务。

验收必须包含实际 Codex 内嵌入口和受影响路径；普通浏览器、HTTP 200 和返回 revision 都不是内嵌验收的替代证据。记录主分支提交、运行制品摘要、启动状态和实际验收结论；未验证的项目明确标为未完成。

## 本轮范围

本轮抽取高频展示积木并完善文档，不改写全部存量代码，也不改变现有布局与用户已确认的滚动规则。账户接入与网关等其他工作树中的变更需由各自任务独立发布，不能在组件整理时被覆盖。
