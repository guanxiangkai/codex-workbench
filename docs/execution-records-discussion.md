# 执行记录：讨论方案，非当前功能

> 当前工作台已移除执行记录。本页供有审计、排障或团队协作需求的使用者参考，不承诺上线，也不表示当前已经自动采集 Codex 的所有执行过程。

## 为什么可能需要

核心记录单位是**任务**，颗粒度比会话更细。一个会话可包含多个任务，每个任务有独立目标、消耗、执行时间和结果。会话用于追溯上下文，任务用于衡量具体工作的资源投入与完成情况；不能把一整段会话直接当成一个任务。

长任务失败时，使用者可能需要知道停止在哪一步、是否产生副作用、能否安全重试，以及结果依据是什么。简单个人工作台可以保持轻量；有多工具流程时可考虑把执行记录作为独立可选模块。

## 信息架构

入口为可选的“执行记录”。列表使用即时搜索、状态、时间范围筛选与任务数量。每条记录呈现任务标题、所属会话、状态、开始时间、执行耗时、Token 消耗和额度来源。点击打开详情，顶部给出任务目标、消耗与时间摘要、结果，正文展示执行尝试、步骤时间线及产物链接。

时间统计区分等待时间、实际执行时间和起止跨度；并行步骤不能简单相加作为任务墙钟耗时。资源统计区分输入、输出和可用的缓存 Token 指标，注明供应方口径；缺失值为未知，不记零。费用只在有可靠计费数据时展示，不能从套餐剩余百分比推算金额。重试产生独立执行尝试，按去重后的用量事件汇总到任务，避免同一消耗被任务和步骤重复累计。

详情分成概览、步骤和证据三部分。步骤显示等待、执行中、成功、失败、取消或未知；每一步独立记录开始/结束时间与脱敏错误。不要把“进程退出”直接等同于“业务成功”。长文本在详情内换行，不挤压列表。

## 页面与状态

| 画面 | 内容与交互 |
| --- | --- |
| 记录列表 | 搜索、状态和时间筛选；示例记录；入口与数量 |
| 成功详情 | 结果摘要、步骤时间线、经过核验的产物链接 |
| 失败详情 | 失败步骤、错误分类、可恢复建议，保留前序已完成步骤 |
| 执行中 | 当前步骤与最近更新时间，不虚构进度百分比 |
| 空数据 | 说明尚未登记记录；区分筛选无结果 |
| 来源失败 | 明确数据暂不可用，显示最近成功快照时间 |

重新执行、取消和删除都不是普通读取。第一版可仅查看，不提供这些按钮；以后添加时须定义幂等键、权限、影响范围和必要确认。不能把“重试”简单映射成重放整条命令。

## 建议数据契约

任务记录包含 `task_id`、`session_id`、`title`、`source`、`status`、`started_at`、`finished_at`、`waiting_ms`、`execution_ms`、`usage`、`attempts`、`steps` 与 `artifacts`。`usage` 保留来源、计量口径、输入/输出/缓存 Token、可选费用与币种；未知字段用空值。额度来源使用非秘密账户引用。执行尝试有独立 `attempt_id`，用量事件有稳定去重标识。步骤含稳定 ID、状态、时间和脱敏错误码。产物只保存授权引用，不自动公开本机绝对路径。缺少终态应显示未知或中断待确认，不擅自补成失败。

记录写入以显式事件为基础，不扫描原始会话正文来猜测成功。对重复事件去重，乱序事件不得把终态回退为运行中。保留期限与清理规则由使用者配置；日志不包含密码、Token、完整提示词或第三方个人数据。

## 扩展前的决策

先确认记录谁的任务、谁能看、数据保存多久、是否需要跨设备以及是否真的需要执行控制。已有恢复分支 `archive/execution-records` 只能作为参考，恢复时基于当前代码移植并重新验证，不整分支覆盖当前界面。

旧脱敏示意图见 [讨论参考](../design/discussions/README.md)。Figma 讨论稿应独立组织，并持续保留“非当前功能”标识。仓库当前仅提供脱敏参考图，设计稿不等于已实现功能。
