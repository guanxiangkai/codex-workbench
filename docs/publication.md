# 公开发布边界

公开副本仅保留当前源码、合成测试、通用说明、第三方许可和脱敏设计材料。公开历史与本机私有开发记录隔离；不得纳入运行数据库、历史 UI 副本、执行标题映射、验收日志或实际账户资源目录。

发布审查范围：

- 文件路径、源码、测试、JSON、HTML、JavaScript 及重新生成的 UI 发布包。
- 个人名称、绝对用户目录、邮箱、私有服务器地址、真实账户标识、带时间戳的本机凭据引用及密钥特征。
- Figma 当前分组导航版的 4 张画板；逐一检查文字节点、图像填充和 PNG 导出。账户名称替换为通用示例，金额、额度与日期已移除。
- 执行记录讨论另附一张独立脱敏的旧方案参考图，明确标记为非当前功能；不公开其他历史页面或原文件链接。
- 测试媒体的来源：音频是脚本生成的正弦波，其他媒体是合成像素或静音结构。
- Git 实际纳入的文件及提交身份；所有作者和提交者使用 GitHub noreply 邮箱，不携带私人邮箱。

官方公开 API 地址、通用回环地址、协议字段名、第三方许可证和标注为合成数据的测试占位值属于可公开技术内容。某些拒绝路径测试故意含无效凭据形状，这些内容不具备认证能力。公共仓库会显示所属 GitHub 账号，此发布不承诺账号匿名。

静态规则扫描与人工审查用于降低遗漏风险，不构成对任意未来修改的保证。后续贡献同样不得加入真实账户配置、凭据、服务器登记、截图中的个人信息或运行日志。

## 持续发布门禁

`contracts` 检查先验证完整可达 Git 历史中的作者与提交者邮箱，再使用固定版本并核对 SHA-256 的 Gitleaks 扫描历史和工作树。扫描禁用行内豁免并完全脱敏，原始扫描报告只存在于临时目录，不上传为 Actions 产物；失败日志只报告阻断原因。分支须经 PR、检查通过且保持最新才能合并。

已公开资料的历史重写只能替换仓库当前分支和标签可达的历史，不能撤回他人的克隆、截图、旧提交缓存或 GitHub 保留的 PR 引用。发现泄漏时应同时核对内容、提交元数据及 GitHub 附属材料，并按实际证据报告清理范围。
